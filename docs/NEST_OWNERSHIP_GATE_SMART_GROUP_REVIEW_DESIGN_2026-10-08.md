## 2. 产品目标和操作路径

选择项目 → 加载已确认档案和候选预填 → 选择/确认组织目录 → 后台分组分析 → 人工处理决策组及例外 → 单独设定允许的操作 → 暴露面按权限消费。

人需要确认的是“这类资产属于谁、凭什么、可以做什么”，不需要逐条填写重复 URL。资产原行、证据和历史保留，聚合只增加视图与可追溯的组关系。

## 3. 门禁判断四件事

| 维度 | 需要的结论 | 典型例子 |
| --- | --- | --- |
| 集团成员关系 | 已确认/候选/无关/冲突/未知 | 属于本集团，但管理单位不明确 |
| 管理单位 | 总部、省公司、市分支、专业子公司、共享、未知 | 苏州软件公司候选，不自动归江苏省公司 |
| 服务地域 | 一个或多个省市、全国、境外、未知 | 总部运营，服务浙江与江苏 |
| 操作权限 | 按项目、对象、动作、有效期允许/拒绝/未知 | 允许公开资料检索，未允许目标主动扫描 |

注册地、管理单位地域、部署地、服务地域、授权地域分别保存。旧 jurisdictions 不直接复制到任何授权字段；历史含义不清的值展示为“旧字段，待确认”。

门禁不是一个总开关。下游动作检查以下组合：

| 动作 | 检查对象与条件 |
| --- | --- |
| 本地归属分析 | 当前项目现有数据，可在无扫描授权时处理 |
| 关于集团/单位的公开信息检索 | 已确认检索主体、允许渠道、排除策略和检索权限 |
| 外部代码/文档的归属核验 | 信息与主体的关联、来源访问权限；第三方平台不当成集团自有域 |
| 访问自有目标、探测或扫描 | 目标属于当前 scope，所需动作单独获准，未过期/未撤销 |

确认“这份资料属于集团”不表示授权扫描承载资料的代码平台、网盘或他人域名。正常招标/采购及转载继续按产品策略排除。保留 Master 现有最终执行授权校验，不用归属组绕过 Native/Broker。

## 4. 选择项目时如何自动预填

优先级：当前项目已保存且确认的字段 → 当前未保存的用户草稿 → 已确认集团组织目录中的关联字段 → 当前项目资产产生的候选建议。低优先级信息不覆盖高优先级。

| 字段 | 自动行为 | 用户工作 |
| --- | --- | --- |
| 项目名称、项目 ID | 自动展示 | 不需重填 |
| 关联集团、项目类型 | 已绑定目录时填入；未绑定按标题/company 提建议 | 第一次确认集团，选择集团总账/单位项目 |
| 主体正式名称 | 已确认目录直接带出；标题不能直接当法律名称 | 确认一次，可绑定已存在实体 |
| 省/市单位列表 | 从已确认目录带出，当前数据出现的候选单位标计数 | 首次处理冲突及目录缺口 |
| 简称、英文名、历史名称 | 目录中已确认值复用；从数据发现的新值作草稿 | 批量接受建议或逐项排除 |
| 官方域名、共享域名 | 已确认目录作为归属证据；新域名只建议 | 查看出处后确认归属规则 |
| 服务地域 | 数据/目录提出多选候选，允许未知和全国共享 | 仅处理没有证据的部分 |
| 授权对象、动作、期限 | 当前项目已有有效授权按原对象显示 | 新对象或新动作明确批准，不自动填允许 |

集团项目的主体是集团总账并关联多个成员实体，不要求把 63 个公司标签塞进一个“主体名称”字符串。单位项目使用自己的范围；项目 3/15 可复用组织知识，不互相复制权限。

每项建议保留 value、entityId、source、支持行数、冲突行数、examplesRef、directoryVersion、policyVersion、dataRevision、状态。状态至少“已保存”“已确认目录”“待接受建议”“冲突”“未知”，不以颜色或概率代替解释。

UI 首屏只呈现项目类型、集团/单位卡、范围摘要和“查看建议”按钮；高级区展开别名、域名、排除项及权限。第一次建立目录后，后续选择项目自动复用。接受建议先进入草稿；保存时 CAS 校验版本。

项目切换立即清空旧项目选择与绑定的批量预览；按项目保留草稿。所有请求/响应绑定 projectId + requestGeneration，过期响应丢弃。筛选复核列表不触发档案覆盖；保存/批量确认必须检查 loadedProjectId 与当前项目一致。

## 5. 智能识别分两层

**先做确定规则与目录匹配**：名称标点/空白规范化、已确认别名、稳定组织标识、已确认官方域名、历史人工结论。品牌、IP/ASN、机房地域、页面标题只有辅助作用。不得无差别删除法人后缀后合并实体。

示例：
- 中国移动通信集团浙江有限公司：规范名可匹配已确认的浙江省公司目录。
- 中移（杭州）信息技术有限公司：先匹配专业子公司；杭州只作为所在地线索。
- 标题出现“浙江移动”，域名为供应商共享站：候选关联，保留供应商/托管冲突。
- company=161.81.120.0/22：网络线索，不能自动产生香港移动法人归属。
- 总部统一域下存在多省入口：集团共享/省级候选分列，未知部分不硬分配。

**模型只补模糊组**：输入去重的单位名称、少量已有标题/证据摘录、候选目录和排除关系；输出候选 entityId、支持证据引用、反证、缺失信息、建议下一步。只允许引用输入中真实存在的实体/证据；实体未知时返回 unknown 或目录补充建议。

模型调用绑定项目、目录和数据版本，经过既有 Native 费用/缓存/权限合同；不得为每条 URL 调一次模型，也不得在 Qoder exposure 内复制运行时。未接入返回规则结果 + model_not_ready。模型不能自动确认集团法律关系、自动授权新目标或掩盖冲突。

规则分值展示为“证据充分/一般/不足”及原因，不包装成准确率。模型建议与人工事实分层保存，人工结论优先；过期人工结论标记待复核，不悄悄改写。

## 6. 后台聚合：导航组与可操作组分开

第一层按候选单位导航：总部/共享、省公司、市分支、专业子公司、境外、关联供应商、冲突、未知。可以在缺少目录时先显示 company 原标签，但明确是“标签候选”。

第二层形成可操作的**归属复核组**。组成员必须在以下关键条件上一致：projectId、候选管理单位及关系类型、域名/托管边界、支持与反证类型、现有人工结论、授权状态/动作边界、证据版本。

| 聚合线索 | 用途 | 必须拆分的情况 |
| --- | --- | --- |
| 同 URL 的协议/跟踪参数差异 | 作为重复观察或同 endpoint 导航 | 查询参数含租户/资源/权限标识、内容有实质差异 |
| 同一精确 host 的多路径 | 主机层导航，聚合重复证明材料 | 多租户、路径分别归不同单位、敏感与公开证据不同 |
| 同一可注册域及一致实体证据 | 域名族导航 | 不同省单位、共享托管、冲突或权限不同 |
| 同公司标签 | 单位候选汇总 | company 来源弱、同名异主体、第三方或历史变更 |
| 同标题/内容指纹/CDN | 辅助模板识别 | 不能单独用于统一归属或授权 |

域名层级使用正确的公共后缀规则，并保留 private suffix/租户边界及算法版本；不能按最后两段将所有 *.com.cn 混成一个单位。现有 exposure 内容簇/域名簇可作线索，不直接当归属组。

一个资产关联在每个分析快照内仅属于一个主复核组，避免总数重复；服务地域为多值标签，地域覆盖数量不相加当资产总量。孤立资产允许单成员组。无法可靠归并的记录进入未知/冲突组，不能为了减少卡片强制合并。

## 7. 页面改成决策组队列

顶部展示“待复核资产数、待复核组数、冲突组数、已完成组数、未处理增量”，并注明分析时间和版本。复核组卡包含：

```
浙江省公司候选 / 某精确主机族   （示例，非实际判断）
总成员 840：规则一致 812，证据不足 20，冲突 8
依据：已确认实体别名 + 官方域规则
反证：8 条出现供应商/托管标识
现有权限：未授予主动扫描
操作：查看支持证据 | 查看全部冲突 | 预览确认 812 条
```

单位导航可以先把相近资产放在一起看；上例中的 812/20/8 必须是分别可操作的子组，不能勾一下把 840 条全放行。数字仅为说明。

默认看 3–5 条按不同证据/域/内容类型选取的代表样本，并显示代表样本覆盖规则；反证和未知计数不能隐藏。全部成员由后端 cursor 分页；人工可以展开逐条修正。大型组有混合特征时先拆分，不把少量样本看过当所有成员已验证。

优先级先冲突/授权影响大/证据已变更，再处理高覆盖且证据一致组；同时支持“先快速确认一致组”和“仅看某省未归属”。URL 列表保留为组内详情和原资产工作台。

## 8. 全组批量复核的正确性

前端提交 groupId，不下载几万 ID 再回传。后端先返回批量预览：分析快照、操作对象 hash、各状态数量、被排除的人工/冲突/失效成员、拟改变内容。确认命令带 operationId、projectId、snapshotId、groupVersion、policyVersion、directoryVersion、expectedActionHash。

后端在事务/可恢复批次协议中重新验证：
1. 所有成员属于该项目且未删除，scope 和当前证据版本仍有效。
2. 快照之后加入的新资产不自动纳入；已删除、撤权、证据或人工决定变化使预览失效，需要重新预览。
3. 无权、第三方、冲突组不能被一致组批量动作覆盖。撤销动作也验证项目关联。
4. 相同 operationId 重放幂等；相同 operationId 携带不同 payload 明确拒绝。
5. 结果报告 applied/skipped/conflicted/failed 及原因，不返回模糊“成功”。审计记录批次与每条旧值/新值及证据引用。

归属确认和赋权是两个动作，可在一个明确列出二者影响的向导中连续完成。需要操作权限时使用既有受控授权机制；归属结论本身不能创建执行 grant。域规则默认精确 host；子域、租户或路径范围由人明确选择，不能泛化到共享平台根域。新资产符合规则可自动归类为候选，仍按其当前授权检查。

超过事务预算时使用 operation 状态机与分块 staging；未完成批次不得向下游发布部分“整组已允许”。撤销授权先立即阻断下游，再更新展示索引；后台恢复不得恢复已撤销权限。保持历史归属/授权原意，迁移不自动扩大权限或重新解释旧 confirmed。

## 9. 几万条的后端处理方式

- 分析任务持久化 queued/running/completed/cancelled/failed，绑定 project/scope/data/policy/directory/algorithm 版本；按稳定主键读取，短事务写中间结果，不把全部 extra_json 载入 UI 或一次长写锁。
- 拆出实体匹配结果、规范 host、支持/反证特征、主组成员索引和分组计数；页面仅取分页组摘要，展开再读成员。
- 初次完整分析后使用数据变更水位增量更新；删除、人工结论、目录/规则变更有失效传播。增量组产生新版本，不修改已提交批量预览。
- 大任务在后端任务队列运行，不占据交互调用的长事务；同项目共享匹配结果，不同时启动重复全量分析。支持取消和崩溃恢复，报告真实已处理数量。
- 项目切换可以展示已有完成快照和新分析进度，清楚标注旧快照，不用空队列表达“已经处理完”。
- 对 project/state/group/member 的索引用实际 query plan 验证。缓存键包含 scope 和版本；其他项目的授权结果不得缓存复用。
- 真实规模验收用临时库 4000/20000/100000 行，保留弱证据、多租户、混合省份、重复 URL、并发更新。测量分析耗时、分页 p50/p95、RSS、数据库/WAL 增长与取消延迟。首版组摘要 p95 < 1 秒作为待验证的交互目标，不是当前实测承诺。

不预先承诺“几万条一定减少到几十组”。现有 63 类 company 只说明导航有聚合空间；最终决策组数量依赖真实域、证据、冲突和授权边界，需完成分析后报告压缩率与未能合并原因。

## 11. 实施顺序与分工

1. **主控 O0：当前页面正确性**。先处理项目响应代次、草稿保护、保存 CAS、成员资格和决定版本校验；明确旧按钮含授权的影响。
2. **主控 O1：项目预填闭环**。复用一个组织目录，从当前 company 生成只读候选，用户确认一次后复用；专业子公司/省公司/地域分列，无模型也可用。
3. **主控 O2：后台聚合复核闭环**。分析任务、组分页、反证拆组、批量预览/确认与审计，选现有一个项目完整验收；不改变未确认真实资产。
4. **主控 O3：规模与权限**。完成增量、崩溃恢复、并发变更、100000 行测试，接入动作权限的既有合同。
5. **主控 O4：模型补助**。仅在 Native 对应能力就绪后接入歧义组辅助，记录费用/证据/失效；Qoder 不复制运行时。
