# Oviraptor：独立聊天主应用与内置业务插件

## 产品边界

本轮目标是一个安装包、一个主窗口中的模块化产品，不是分别发布 Assets 和 Nest 安装包。

- 主应用提供独立 Chat、项目空间选择、配置、主题及共享环境管理
- Assets 内置插件负责资产页面、任务列表、归属、公开暴露面及相关日志
- Scanning 内置插件负责扫描工作台、调查任务、结果、知识与策略及运行日志
- HackerOne 作为兼容内置插件保留，继续使用原凭据配置门禁
- 后台执行与沙箱属于内部服务，没有新增面向用户的沙箱应用入口

通用聊天消息使用独立 Conversation 存储。扫描中的调查时间线仍然是任务控制和证据界面；将它移入主聊天会错误地改变任务、收据和证据的归属，因此保留在扫描插件中。

## 插件的含义

这里是**随程序编译和打包的可信内置插件**。插件提供声明、工作页面和受限的主应用调用接口。当前不加载远程 JavaScript、任意本地插件目录或用户提供的可执行 manifest，也没有插件市场或独立更新机制。

- `src/plugins/`：稳定插件 ID、页面与能力声明、启用偏好及受限调用
- `src/shell/`：主窗口导航、可信组件映射和工作空间接口
- `src/features/assets/workspace/`：资产工作空间
- `src/features/sentinel/workspace/`：扫描工作空间
- `src/features/hackerone/workspace/`：HackerOne 工作空间
- `src/features/conversations/`：主应用的独立聊天，不属于扫描插件

启停偏好只控制本机界面和主应用插件入口，不是安全授权。停用不删除数据、不撤销后台任务、不修改模型或 Worker 配置。执行权限、预算、范围与取消仍由原领域后端负责。已经明确提交并开始的恢复流程按原始项目和参数完成，不因界面卸载自动中断或重新执行。

## 聊天与插件联动

本轮主应用调用限于明确的只读查询和页面导航：

1. 在当前项目中查找已经存在的资产或扫描记录
2. 把已选记录以引用形式关联到当前会话
3. 明确点击后打开对应插件工作空间

关联数据不会自动进入模型上下文，也不会自动启动扫描。当前页面不具备精确实体深链合同，因此“打开工作空间”不冒充“已经选中这条资产/扫描”。

插件声明中的业务能力说明与真正可调用命令分开。能力声明只是前置要求说明，不证明提供商可达，也不是授权或派发许可。它不提供通用 `invoke(command, args)`，不意味着模型可以执行它。后台扫描仍须走原有工作台与后端门禁。

## 数据与生命周期

- 项目空间继续是业务归属边界，插件不复制一份平行数据库
- 会话删除只影响其消息、回复与引用，不能级联删除资产或扫描证据
- 切项目、停用插件和组件卸载使旧读取结果失效，旧响应不能覆盖新项目
- 资产中断任务的恢复属于明确用户操作，不应因插件重新挂载重复启动
- 原配置方案、凭据、Worker 设置、扫描历史和资产归属关系继续保留

## 本地体验方式

请先保存自己的未提交改动。建议使用单独工作目录体验，不覆盖正在开发的主分支：

```bash
git fetch origin refactor/project-scoped-applications-20261013
git worktree add --detach ../Oviraptor-plugin-preview origin/refactor/project-scoped-applications-20261013
cd ../Oviraptor-plugin-preview
npm ci
npm run build
npm run tauri dev
```

原仓库的 Node.js、Rust、Python 和平台构建前置条件仍然适用。`npm run build` 只验证前端；`npm run tauri dev` 才会编译并运行桌面壳。

注意：独立源码目录不会自动隔离应用数据目录。若本地预览使用相同应用标识，可能读取同一份项目和配置；请退出旧实例，并先通过正常备份方式保留应用数据。开发构建不是生产安装包验收。

体验时依次检查：

1. 主聊天的新建、历史、无模型保存与项目切换
2. 内置插件的入口、停用和重新启用；确认历史数据仍在
3. 资产与扫描原页面、配置和日志入口
4. 聊天关联同项目业务记录，随后打开插件工作空间
5. 连续切项目、关闭面板、重复点击，以及操作失败的就近提示

## 明确未包含

- Computer Use 实现：这里只借鉴能力插件的产品形式，没有新增鼠标、键盘或浏览器操控功能
- 模型自主选择并执行插件工具、跨应用任务编排
- 第三方插件安装、签名、权限审批和升级协议
- 独立插件进程、独立 Rust crate 或独立安装包
- 自动将历史扫描调查迁移为普通聊天

这些能力需要各自的执行合同和验收，不因增加插件目录而自动具备。

## 验证记录

本轮没有改动 Rust 源码、Cargo/JavaScript 依赖锁文件，也没有操作用户电脑。前一批次的 Rust 结果是历史验证，不计为本轮重跑。

- 前端类型检查和生产构建：通过
- 实际 Vue 应用挂载到 jsdom、使用明确的模拟 Tauri IPC：16 / 16 场景通过，无 Vue 运行错误或未知 IPC 调用
- 覆盖空聊天、默认折叠面板、显式关联查询、跨项目迟到响应、插件导航与启停、损坏偏好的勾选回退、归档只读和长文字内容保留
- 实际浏览器像素、窄屏布局与 macOS 桌面：未验收。云端 Chromium 因 Unix socket 权限失败；另一个云浏览器无法访问执行环境本地服务。DOM 测试不替代视觉验收
- 真实模型提供商、目标扫描、安装包构建与运行：本轮未执行

冻结源码的最终聚合：`npm run test:ui` 1,047 / 1,047 通过；`npm run test:asset-exposure` 72 / 72 通过。独立审查另运行 118 项聚焦检查通过；这些测试与聚合重叠，不将数量相加。`npm run build` 包含 Vue/TypeScript 类型检查与 Vite 生产构建。最终测试前后源码摘要核对一致。

新增套件可用 `npm run test:plugins` 单独执行；主窗口的恢复与偏好回归在原 `test:project-deletion` 套件中继续验证实际 App 组件，而不是替换成静态文本断言。

本轮额外修复了插件生命周期中的异步问题：失败的偏好保存恢复原始复选框显示；扫描插件切换不会释放其他资产操作的互斥状态；已提交恢复流程在页面卸载后仍完成原始调用，主窗口保留恢复收据并重新读取后台状态，防止旧提醒重复提交。后台核对失败只提供只读重试，不自动再次启动任务。

现有非 reprobe 恢复仍由确认旧任务和创建替代任务两次后端调用组成，并非本轮改造成事务。若确认成功而启动失败，界面明确显示部分完成的原因；不会伪造成功或自动重试。
