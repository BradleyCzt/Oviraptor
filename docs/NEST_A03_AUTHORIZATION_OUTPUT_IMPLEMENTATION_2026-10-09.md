## 两种完整三侧输出必须都支持

1. 完整三侧且 Rust 确认跨账号对象访问：单控制组 verified=1，原 finding/body/身份/对象绑定存在，Root只能解释已确认事实和未覆盖范围。
2. 完整三侧且 cross被拒绝或控制结果不构成漏洞：单控制组 verified=0，正常 completed，仍有三次真实响应与原费用。输出监督应成功触发，不能因为没有 finding 而视为不可信/不产生事件。

首片必须支持现实际一个 child 含 N 个已登记控制组，不硬限 N=1。每个 contractKey 恰好 owner/cross/tester 三侧 known received，逐组验证原签名、身份/对象/控制语义；全 child actual claims、side seals、target消费精确为 3*N，verified 总数等于 Rust逐组结果之和（0到N）。一个正常 closed child 的输出封套包含已冻结全组汇总，作为一个稳定 output source；group集合以原task_slice/control集合为准，terminal后不能增减漂移。partial/failed/cancelled/unknown sent 不发行正常outputseal，不伪造verified=0。角色输出不需要新增 child SDK：Authorization当前是实际HTTP角色，付费的是后续Root评估。

## Typed source 与生产事务

新增私有 `AuthorizationOutputGuard` / `FreshAuthorizationOutputReceipt`，只由实际正常 finalization producer 创建。不能接收 caller JSON/自报 usage、当前已完成行拼装任意签名器，不能 saved receipt补签。

建议 API 分两阶段：

- `capture_before_on(original IMMEDIATE tx, actor, child, verifiedBirth)`：原作用域与任务控制合同/live worker/原权限，完整三侧原side receipts+fees+artifact bytes，原Rust控制判断与已结算usage，原SDK/execution退出/真实HTTP不在途，固定事件floor。抓取原 source/cap/预算，private guard绑定同Connection，持实际idle跨关闭与后续paid。
- `issue_after_on(same tx, actor, child, guard, actualMessageId)`：验证 actual authorization_result route/correlation/revision/payload语义、一次ACK/outbox、正常completed/撤权/lane释放，原side artifacts/费用未变化；签名保存一张 immutable receipt，失败回滚该交付事务，不以修复路径补签。
- `read_original_on(snapshot, actor, child or sourceId)`：严格原 birth/domain/signature/canonical JSON/hash/schema、原scope/控制合同/三侧费用和原bytes、关闭及ACK/outbox；缺失None，冷改错误传播；不创建表、不backfill、不重新锁住外层持有的inode。

签名域与 purpose 应独立 Authorization output；复用原 verifiedBirth私有keyscope，binding包含root/scan/attempt/target/Cepoch/fence/assignment/worker/contractKey、三个sideReceiptId与artifact原byteshash、Rust verified0/1、原费用、actualmessage+outbox。只冻结原事件，排除 Root自己新增费用、TTL、全局余额，保持重放稳定。

优先复用现 side原签与collection verifier。新 pure collector应支持verified0：逐side验证签名与费用、三侧响应，最后由确定性Rust函数产出逐组结果和verified总数；不能因没有finding绕过原证据验证。特别禁止沿用 finding verifier 的“恰好3个claims/全child消费3”单组假设：必须逐contract exact3，再全child聚合精确3*N，拒孤立/额外/缺失contract或side。涉及SDK使用实际原费用回执与idle，HTTP未知保持indeterminate，不退款、不重发。
